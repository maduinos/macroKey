# macroKey

8버튼 매크로 키패드. **패드는 앱 없이 USB 키보드/마우스로 동작**하고,
PC 앱은 설정·녹음할 때만 켭니다.

버전: 펌웨어 `0.9.6` / 앱 `0.17.0`

세 단계면 끝납니다 — **① 하드웨어를 만들고 ② 앱을 받아 실행하고 ③ 키를 녹음합니다.**
펌웨어는 앱이 알아서 굽습니다.

---

## ① 하드웨어

**기본은 아두이노 Pro Micro(ATmega32u4)**입니다. 큰 매크로를 많이 넣고 싶을 때
쓰는 확장 선택지로 ProMicro RP2040을 지원하고, 둘은 같은 펌웨어 소스로 돕니다.

| 보드 | 매크로 용량 | 비고 |
| --- | --- | --- |
| **Pro Micro (ATmega32u4)** — 기본 | 308 레코드 | **5 V / 16 MHz 버전**이어야 합니다 — 펌웨어가 16 MHz로 빌드돼 8 MHz 판은 USB가 안 잡힙니다 |
| ProMicro RP2040 (16 MB) — 확장 | 21,801 레코드 | 용량이 70배. 긴 마우스 매크로를 여러 개 넣을 때 |

### 준비물

- 보드 1개 (위 표에서 하나)
- 순간접점(momentary) 스위치 **8개** — 만든 사람은 **망가진 키보드에서 뽑은 체리 MX 스위치**를
  썼습니다. 택트 스위치도 됩니다. 접점 두 개짜리면 무엇이든 상관없습니다
- WS2812B(NeoPixel) **1픽셀** 모듈 1개
- 330~470 Ω 저항 1개, 100 µF 전해 커패시터 1개
- **1 m 이하 데이터용** USB 케이블 (충전 전용 케이블은 전압이 떨어져 색이 틀어지거나 리셋됩니다)
- 케이스 — 아래 참고

### 케이스 (3D 프린트)

Thingiverse의 **[Stream Cheap (Mini Macro Keyboard)](https://www.thingiverse.com/thing:2822140)**
(DaveM, CC BY-SA)를 씁니다. **체리 MX 4×2 = 8키** 배열이라 macroKey의 키 수와 그대로
맞습니다. 이 프로젝트가 8버튼인 이유이기도 합니다.

| 파일 | 용도 |
| --- | --- |
| `StreamCheap_Base.stl` | 아래 몸통 (보드가 들어갑니다) |
| `StreamCheap_Faceplate.stl` | 스위치 8개를 잡아 주는 윗판 |
| `StreamCheap_Icons.pdf` | 투명 키캡에 끼울 아이콘 — 인쇄해서 잘라 넣습니다 |

체리 MX용 **투명(relegendable) 키캡**을 쓰면 아이콘을 넣을 수 있습니다.
케이스에 딸려 오는 `StreamCheap.ino`는 원작자의 별개 펌웨어이니 **쓰지 마세요** —
macroKey 펌웨어는 앱이 굽습니다.

### 배선

버튼은 한쪽을 신호 핀에, 반대쪽을 GND에 연결합니다. 내부 풀업을 쓰므로 외부 저항은
필요 없습니다.

| 연결 | Pro Micro (5 V 로직) | ProMicro RP2040 (3.3 V 로직) |
| --- | --- | --- |
| 버튼 1~8 | D3~D9 + **D10** (8번만 위쪽 줄) | GP2 ~ GP9 |
| WS2812B DIN | **A0** (330 Ω 직렬 저항 경유) | **GP21** (330 Ω 직렬 저항 경유) |
| **WS2812B VDD** | **VCC** = 5 V (`RAW` 아님) | **3V3** = 3.3 V (`RAW` 아님) |
| WS2812B GND | GND (버튼과 공통) | GND (버튼과 공통) |

**규격상 WS2812B는 5 V 부품이지만**(V<sub>DD</sub> 3.5~5.3 V) **RP2040 판에서는 3.3 V로도
동작합니다 — 직접 확인했습니다.** 규격 밖이라 보증되지는 않고, 5 V 때보다 어둡습니다.

그럼에도 그 보드에서는 3.3 V가 낫습니다. WS2812B의 입력 하이 임계가 0.7 × V<sub>DD</sub>라서,
3.3 V 로직인 RP2040에서 모듈만 5 V에 물리면 임계가 3.50 V로 올라가 3.3 V 데이터로는
미달입니다 — 되다 안 되다 하는 가장 나쁜 형태로 나타납니다. 3.3 V로 급전하면 임계가 2.31 V로
내려가 여유가 충분합니다.

100 µF 커패시터는 모듈 가까이에서 VCC–GND 사이에 답니다. **1000 µF는 쓰지 마세요** —
돌입 전류로 USB 포트 보호가 걸립니다.

> **RP2040은 보드에 달린 LED가 아닙니다.** GP21에 외부 모듈을 연결합니다. 온보드 LED는 보드마다
> 핀도 종류도 달라(클론은 GP17, SparkFun 판은 GP25) 펌웨어가 건드리지 않습니다.<br>
> **Pro Micro에는 D11이 없습니다.** Leonardo용 자료를 그대로 따라 하면 없는 핀에 배선하게 됩니다.<br>
> **Pro Micro에는 리셋 버튼이 없습니다.** 배선할 때 `RST`–`GND`에 닿을 점퍼선을 하나 미리
> 꽂아 두세요. 잘못된 펌웨어에서 빠져나오는 유일한 길입니다.

**그림 배선도**(핀 위치, 버튼 1개 상세, 전체 결선도)를 인쇄해서 작업대에 두고 쓰세요.

- [Pro Micro 배선 가이드](https://maduinos.github.io/macroKey/boards/wiring-promicro.html)
- [ProMicro RP2040 배선 가이드](https://maduinos.github.io/macroKey/boards/wiring-promicro-rp2040.html)

핀 맵 전체와 조립 순서는 [`docs/boards/promicro.md`](docs/boards/promicro.md) ·
[`docs/boards/promicro-rp2040.md`](docs/boards/promicro-rp2040.md)에 있습니다.

## ② 앱 받기

[**최신 릴리스**](https://github.com/maduinos/macroKey/releases/latest)에서 내려받습니다.
설치 과정도, Python도 필요 없습니다.

| | |
| --- | --- |
| Windows | `macrokey-windows-x86_64.exe` — 받아서 실행 |
| Linux | `macrokey-linux-x86_64` — `chmod +x` 후 실행 |

Linux에서 앱이 패드의 USB 시리얼 포트를 열지 못하면 계정을 `dialout` 그룹에 넣고 다시
로그인하세요. 키보드·마우스 HID 동작만 쓸 때는 필요 없습니다.

```bash
sudo usermod -aG dialout "$USER"   # 실행 후 로그아웃 → 로그인
```

## ③ 펌웨어 — 앱이 알아서 굽습니다

**패드를 USB로 꽂고 앱을 켜면 됩니다.** 앱이 어떤 보드인지 알아보고, macroKey 펌웨어가 없거나
낡았으면 확인을 한 번 받은 뒤 직접 설치합니다. arduino-cli도 코어도 라이브러리도 필요
없습니다 — 완성된 이미지가 실행 파일 안에 들어 있습니다.

손이 필요한 곳은 한 군데뿐입니다.

| 보드 | 첫 플래싱에 필요한 동작 |
| --- | --- |
| **Pro Micro (ATmega32u4)** | **없습니다.** 꽂고 앱을 켜면 끝입니다 |
| ProMicro RP2040 | **BOOTSEL**을 누른 채로 USB를 꽂습니다 — 첫 한 번만 |

**Pro Micro는 그냥 됩니다.** 공장 상태로 스케치가 없으면 Caterina 부트로더가 그대로 떠 있어
앱이 알아보고 바로 굽고, 스케치가 들어 있어도 앱이 1200 bps 터치로 Caterina에 넣습니다.
`RST`–`GND` 더블탭은 첫 설치용이 아니라 **USB가 죽은 펌웨어에서 빠져나오는 복구용**입니다.

**RP2040만 첫 한 번 BOOTSEL이 필요합니다.** 공장 데모 펌웨어가 시리얼 포트를 열지 않아서
"부트로더로 가라"고 부탁할 상대가 없기 때문입니다. 앱이 그 문장을 띄우고 `RPI-RP2` 드라이브가
나타나는 것을 지켜보다가 즉시 굽습니다. **한 번 올라간 뒤로는 이쪽도 완전 자동입니다.**

> **USB 허브에 물리지 마세요.** 메인보드 직결 포트에 꽂아야 한 번에 붙습니다.

## 쓰는 법

1. 앱 실행 → 패드 연결
2. 키 칸에서 단축키를 넣거나, **패드 키 3초 홀드**로 녹음
3. 같은 키를 다시 3초 홀드하면 저장 (더블 슬롯 녹화는 탭 후 250 ms 안에 다시 홀드)
4. 키 칸을 클릭하면 **반복**(1~255회)을 정할 수 있습니다 — 녹음과 단축키 둘 다 되고,
   탭과 더블이 각각 따로 갖습니다
5. 앱 종료 — 패드는 HID로 계속 동작

매크로 재생 중에는 픽셀이 **시안**으로 맥동하고, 끝나면 **초록**으로 한 번 깜빡입니다.

**반복 중에는 패드의 아무 키나 누르면 멈춥니다.** 멈추려고 누른 키는 자기 바인딩을
실행하지 않습니다. 반복이 1회일 때는 예전처럼 눌린 키가 큐에 쌓였다가 매크로가 끝난 뒤
실행됩니다.

단축키에 반복을 걸면 앱이 그 단축키를 1-단축키 매크로로 감싸 50 ms 간격을 넣습니다.
슬롯 하나와 레코드 두 개를 씁니다. 다시 1회로 내리면 풀립니다.

반복은 **"실제 타이밍"으로 녹음한 홀드**와 같이 쓸 때 의미가 큽니다. 10초 홀드 하나가
6 레코드인데 패드 전체 용량이 308 레코드라, 같은 동작을 255번 녹음하는 것은 애초에
들어가지 않습니다. 반복 횟수는 저장 공간을 한 바이트도 쓰지 않습니다.

마우스 녹화는 기본적으로 **현재 포인터 기준**입니다. 클릭은 현재 위치에서, 이동·드래그는
현재 위치로부터 상대적으로 재생됩니다. 화면의 같은 위치를 꼭 눌러야 할 때만 실험 기능인
`Fixed screen`을 켜세요.

포인터 가속을 끄면(flat) 마우스 매크로가 녹화된 위치에 더 정확히 떨어집니다. 앱이 한 번
물어보고, 승낙하면 데스크톱 설정을 **영구적으로** 바꿉니다 — Linux는 GNOME `accel-profile`,
Windows는 "포인터 정확도 향상"입니다. 되돌리는 방법은 그 대화상자가 알려줍니다.

Wayland에서 녹음이 안 되면 첫 실행 안내에 따라 `input` 권한을 한 번 허용하세요. 이 권한은
계정의 프로그램이 비밀번호를 포함한 모든 키보드·마우스 입력을 읽을 수 있는 강한 권한입니다.
macroKey는 빨간 녹화 표시가 켜진 동안에만 입력 장치를 엽니다.

언어는 **도움말 > 언어**에서 고릅니다(한국어·영어, 기본값은 시스템 로케일 자동 감지).
바꾼 언어는 **다음 실행부터** 적용됩니다.

자세한 UI 설명: [**사용 설명서**](https://maduinos.github.io/macroKey/manual.html)

## 업데이트

**앱과 펌웨어는 스스로 최신을 따라갑니다.** 앱은 시작할 때 GitHub 릴리스를 한 번 확인해
새 버전이 있으면 내려받아 설치하고(적용은 다음 실행), 패드를 연결할 때마다 패드의 펌웨어가
앱이 가진 것보다 낮으면 그 자리에서 올려 씁니다. 프로필 레이아웃은 앱과 펌웨어가 **같은
스키마로 합의해야** 하고, 한쪽만 뒤처지면 조용히 어긋나기 때문입니다.

받은 파일은 릴리스가 함께 올린 `SHA256SUMS.txt`와 대조한 뒤에만 씁니다. 해시가 없거나 맞지
않으면 아무것도 남기지 않습니다. 보드별 펌웨어 이미지가 실행 파일 안에 들어 있어서 펌웨어
업데이트는 보통 오프라인에서 끝납니다 — 네트워크는 **새 앱**을 가져올 때만 씁니다.

**도움말 > 업데이트 확인**으로 언제든 직접 확인할 수 있고, 같은 메뉴에서 자동 업데이트를
끌 수 있습니다. `MACROKEY_NO_UPDATE=1`은 앱 전체의 네트워크 확인을 막습니다.
