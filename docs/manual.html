01

처음 연결하기

핵심은 앱이 없어도 키패드가 동작한다는 것입니다. 펌웨어만 올리면 평범한 USB HID 키보드입니다. 앱은 긴 텍스트·이미지·셸 명령·LED 상태 표시를 얹는 증폭기이지 필수 런타임이 아닙니다. 그래서 1단계만 해도 쓸 수 있습니다.

  1. 펌웨어를 올린다

    Pro Micro는 리셋 버튼이 없으니 RST–GND를 빠르게 두 번 단락시켜 부트로더(8초)를 띄운 직후에 upload를 실행합니다.

    arduino-cli compile --fqbn SparkFun:avr:promicro:cpu=16MHzatmega32U4 arduino/macrokey
arduino-cli upload  --fqbn SparkFun:avr:promicro:cpu=16MHzatmega32U4 -p /dev/ttyACM0 arduino/macrokey

    여기까지만 해도 키 8개가 Ctrl+Alt+Shift+1~8을 보냅니다. 이 조합을 선점하는 프로그램이 거의 없어서 기존 단축키를 뺏지 않습니다.

  2. 호스트 앱을 설치한다

    python -m pip install -e "host[input]"          # Linux / macOS
python -m pip install -e "host[input,windows]"  # Windows (이미지 클립보드 포함)

    pyserial만 필수입니다. pynput이 없으면 매크로 녹화와 호스트 액션이 비활성화되고, 나머지는 그대로 동작합니다.

  3. 연결을 확인한다

    macrokey ports    # 포트 목록. * 표시가 유력 후보
macrokey info     # 장치 정보와 프로필 동기화 여부

    info는 펌웨어 버전, 프로토콜 버전, 키/LED/레이어 개수, 그리고 장치와 PC의 프로필이 같은지를 알려줍니다. in sync: no가 나오면 macrokey push로 맞추면 됩니다.

    포트가 안 보이면 사용자가 dialout 그룹에 없을 수 있습니다: sudo usermod -aG dialout $USER 후 재로그인.

02

누르는 방식 — 제스처와 레이어

물리 키는 8개뿐이지만 어떻게 누르느냐와 지금 어느 레이어냐로 96가지를 구분합니다. 이게 이 키패드의 전부라고 해도 됩니다.

제스처동작발화 시점주로 넣는 것
TAP짧게 눌렀다 뗌뗄 때 즉시기본 단축키
DOUBLE250 ms 안에 두 번두 번째 탭드물거나 되돌리기 어려운 동작
HOLD400 ms 넘게 유지임계 시간에 도달할 때레이어 전환, 반복

DOUBLE을 안 쓰는 키는 느려지지 않습니다. 해당 키의 DOUBLE 슬롯이 비어 있으면 TAP을 떼는 즉시 내보내고, 채워져 있을 때만 250 ms를 기다립니다. 지연 비용은 그 기능을 실제로 쓰는 키만 냅니다. 자주 쓰는 키에는 DOUBLE을 비워 두세요.

HOLD 슬롯에 레이어 계열 액션이 들어 있으면 누르고 있는 동안만 유효한 momentary 레이어가 됩니다. 그 외 액션이면 400 ms에 한 번 발화합니다. 기본값은 8번 키를 홀드하는 동안 레이어 1(미디어)입니다.

레이어가 0이 아니면 LED가 그 레이어 색으로 물듭니다. 픽셀이 하나뿐인 이 키패드에서 LED의 가장 중요한 역할이 이것입니다. 지금 어느 레이어인지 눈으로 확인하지 못하면 레이어는 실전에서 못 씁니다.

코드(chord)는 두 키를 동시에 누르는 조합입니다. 40 ms 안에 함께 눌리면 코드로 보고, 개별 키의 TAP은 취소됩니다. 기본값으로 1번+2번 = 실행 중인 호스트 액션 중지가 들어 있습니다. 긴 매크로가 폭주할 때의 비상 정지입니다.

03

기본으로 들어 있는 것

펌웨어를 처음 올렸을 때와 앱을 처음 설치했을 때 양쪽이 똑같이 갖는 값입니다. 그래서 첫 연결에서 "동기화 안 됨"이 뜨지 않습니다.

레이어키 · 제스처동작

0 Base8 HOLD누르고 있는 동안 레이어 1
1 Media1–4 TAP볼륨 −, 볼륨 +, 음소거, 재생/일시정지
1 Media5–7 TAP호스트 액션 토큰 0 · 1 · 2 (비어 있음 — 직접 채우는 자리)

미디어 키(레이어 1의 1–4번)는 기본 빌드에서 동작하지 않습니다. Arduino AVR 코어의 Keyboard 라이브러리에는 consumer page(볼륨·재생)가 없습니다. 펌웨어는 이 액션을 무시하고 시리얼로 보고만 합니다. 쓰려면 HID-Project를 설치하고 Config.h의 MK_USE_HID_PROJECT를 1로 바꿔 다시 올리세요.

arduino-cli lib install "HID-Project"

04

키 설정하기 (GUI)

macrokey를 인자 없이 실행하면 편집기가 열립니다. 화면은 레이어 탭 4개이고, 각 탭은 키 8행 × 제스처 3열의 격자입니다. 96개 슬롯이 그대로 화면에 있습니다.

  1. 슬롯을 고른다

    레이어 탭을 고르고, 원하는 키 행과 제스처 열이 만나는 칸을 클릭합니다. 칸에는 현재 들어 있는 동작이 표시돼 있습니다 (-는 비어 있음).

  2. 동작을 고르고 값을 넣는다

    편집 창에서 Action을 고르면 Value에 무엇을 넣어야 하는지 아래 힌트로 나옵니다. 액션 종류별로 필요한 값은 5장에 정리했습니다.

    OK를 누르는 순간 값이 검증됩니다. 잘못된 단축키 이름은 장치에 쓸 때가 아니라 여기서 바로 걸립니다.

  3. 저장하고 장치에 쓴다

    Save는 PC의 profile.json에만 저장합니다. 키패드에 실제로 반영되려면 Write to device를 눌러야 합니다. 이 둘은 다릅니다.

    Write to device를 누르기 전까지 키패드는 바뀌지 않습니다. 편집기에서 아무리 바꿔도 EEPROM에 쓰기 전에는 예전 설정으로 동작합니다. 뭔가 바꿨는데 반영이 안 된다면 십중팔구 이겁니다.

Read from device는 반대 방향입니다. 장치에 있는 프로필을 읽어 편집기로 가져옵니다. 다른 PC에서 설정한 키패드를 이어받을 때 씁니다. 이때 호스트 액션은 덮어쓰지 않습니다 — 장치는 토큰 번호만 갖고 있고 그 뒤의 실제 동작은 PC에만 있기 때문입니다.

05

키에 넣을 수 있는 것

액션은 장치에서 끝나는 것과 PC가 받아서 처리하는 것으로 나뉩니다. 이 구분이 실사용에서 중요합니다. 장치 액션은 앱이 꺼져 있어도 동작하고 지연이 1 ms 미만입니다.

수식키를 +로 잇고 마지막에 일반 키 하나를 씁니다. 순서는 상관없습니다.

06

매크로 녹화

직접 한 동작을 그대로 키에 굽는 방법입니다. 편집 창의 Record… 버튼 또는 macrokey record로 시작합니다.

  1. Start를 누르고 실제로 해 본다

    녹화 중에는 LED가 빨강으로 맥동합니다. 조용히 키 입력을 기록하지 않습니다. Esc를 누르면 멈춥니다.

  2. 앱이 정리한 결과를 확인한다

    사람이 친 그대로 저장하면 재생도 사람 속도로 느리게 나옵니다. 그래서 앱이 다음을 자동으로 합니다.

    • 수식키 접기 — ctrl↓ c↓ c↑ ctrl↑를 hotkey ctrl+c 하나로
    • 지연 양자화 — 10 ms 단위로 반올림하고 40 ms 미만 간격은 버림
    • 연속 문자 병합 — 낱개 타자를 text 액션 하나로
    • 자기 입력 제외 — 녹화 중 키패드 자신이 보낸 입력은 무시

    정리된 결과가 사람이 읽을 수 있는 목록으로 나옵니다. 확인하고 Bind를 누르면 해당 슬롯에 들어갑니다.

  3. 장치에 쓴다

    녹화 결과가 장치 액션 하나로 표현되면(단일 단축키 등) EEPROM에 굽고, 아니면 호스트 액션으로 저장한 뒤 슬롯에는 토큰만 넣습니다. 이 배치는 앱이 알아서 하므로 신경 쓸 필요가 없습니다. 마지막에 macrokey push 또는 Write to device.

07

호스트 액션 — 긴 것, 똑똑한 것

EEPROM 1 KB에 넣을 수 없는 것들이 여기 들어갑니다. 긴 텍스트, 이미지 클립보드 붙여넣기, 셸 명령. 장치는 EV t=host tok=N 한 줄만 흘려보내고 실제 일은 PC가 합니다. 앱이 꺼져 있으면 아무 일도 일어나지 않습니다.

호스트 액션을 만드는 GUI는 아직 없습니다. 편집기에서는 "몇 번 토큰을 쓸지"만 고를 수 있고, 그 토큰이 실제로 무엇을 하는지는 profile.json의 host_actions를 직접 편집해서 정합니다. 녹화 기능은 예외로, 필요할 때 토큰을 자동으로 만들어 줍니다.

type하는 일params
hotkey단축키 전송hotkey, hold_ms
text텍스트 타이핑text
clipboard_image이미지를 클립보드에 넣고 붙여넣기path, paste, press_enter
shell명령 실행 (기다리지 않음)command, cwd
delay대기ms
layer장치 레이어 전환layer
sequence여러 액션을 순서대로steps
stop실행 중인 호스트 액션 중지—
noop아무것도 안 함—

예: 토큰 0에 이미지 붙여넣기 넣기

profile.json을 열고 host_actions에 항목을 추가합니다. 기본 프로필에서 레이어 1의 5번 키가 이미 토큰 0을 가리키고 있으므로, 이것만 채우면 바로 동작합니다. 

"host_actions": {
  "0": {
    "type": "clipboard_image",
    "name": "도장 이미지",
    "params": {
      "path": "macros/macro_1.png",
      "paste": true,
      "press_enter": false
    }
  },
  "1": {
    "type": "text",
    "name": "서명",
    "params": { "text": "정우현 / Maduinos\n" }
  },
  "2": {
    "type": "shell",
    "name": "터미널 열기",
    "params": { "command": "gnome-terminal" }
  }
}

path가 상대 경로면 host/ 기준입니다 — macros/macro_1.png는 host/macros/macro_1.png를 가리킵니다. command는 문자열로 쓰면 셸 문법으로 쪼개지고, 배열로 쓰면 그대로 전달됩니다.

예: 여러 동작을 순서대로

"7": {
  "type": "sequence",
  "name": "회의록 템플릿",
  "params": {
    "steps": [
      { "type": "hotkey", "params": { "hotkey": "ctrl+n" } },
      { "type": "delay",  "params": { "ms": 300 } },
      { "type": "text",   "params": { "text": "## 회의록\n일시: " } }
    ]
  }
}

폭주 방지가 걸려 있습니다. 시퀀스에는 최대 스텝 수와 총 실행 시간 상한이 있고, 1번+2번 키를 동시에 누르면 실행 중인 호스트 액션이 즉시 중지됩니다. 긴 시퀀스를 만들 때 이 조합을 기억해 두세요.

파일을 고친 뒤에는 앱을 다시 시작하거나, GUI에서 Read from device 없이 그냥 껐다 켜면 반영됩니다. 호스트 액션은 장치에 쓰지 않으므로 push는 필요 없습니다.

08

CLI로 하기

모든 명령이 GUI 없이 동작합니다. 데스크톱 세션이 없는 장비에서 쓰거나 스크립트로 묶을 때 이쪽이 편합니다.

명령하는 일
macrokey편집기 창 (기본값)
macrokey ports시리얼 포트 목록. *가 유력 후보
macrokey info장치 정보 + 프로필 동기화 여부
macrokey pushPC 프로필을 장치에 기록
macrokey pull장치 프로필을 JSON으로 출력
macrokey pull --save읽은 것을 PC 프로필로 채택
macrokey monitor키를 누를 때마다 이벤트 출력. 배선 확인에 최적
macrokey daemon창 없이 호스트 액션 + LED만 실행
macrokey record --key N녹화해서 슬롯에 바인딩
macrokey state <상태>실행 중인 앱에 상태 이벤트 전송

전역 옵션: --port <포트>(생략하면 자동 탐색), --verbose, --version. 

# 3번 키의 hold 슬롯에 녹화해서 넣기
macrokey record --key 3 --gesture hold --layer 0 --name "빌드 실행"

# 배선이 맞는지 확인 — 키를 누르면 어느 키인지 찍힘
macrokey monitor

조립 직후에는 macrokey monitor부터 돌리세요. 키를 하나씩 누르면 EV t=key k=0 g=tap 같은 줄이 찍힙니다. 번호가 어긋나거나 아무것도 안 나오면 그 키의 배선 문제입니다. 프로필을 건드리기 전에 하드웨어부터 확인하는 게 빠릅니다.

09

LED로 상태 보기

픽셀 하나가 네 가지 소스를 우선순위로 합성해 보여줍니다. 위에 있는 것이 이깁니다.

우선순위소스어떻게 보이는가
1키 누름흰색으로 120 ms 반짝 — 어느 키든 동일
2레이어레이어 색. 실질적으로 가장 유용한 용도
3호스트 앰비언트상태 색 + 효과 (breathe · blink · pulse)
4기본 씬프로필에 저장된 바탕색

앰비언트를 쓰려면 앱이 떠 있어야 합니다. macrokey daemon을 띄우면 유닉스 소켓이 열리고, 아무 스크립트나 거기에 JSON 한 줄을 쓰면 LED가 반응합니다. 

macrokey daemon &
macrokey state running --progress 0.5
macrokey state error --severity critical
macrokey state idle

--progress는 8픽셀 스트립이면 진행률 바가 되지만, 픽셀 1개인 지금은 밝기로 나타납니다 — 0.3이면 상태 색의 30% 밝기. 거칠지만 작업이 돌아가고 있다는 것은 읽힙니다. 앱을 끄면 3초 뒤 장치가 자동으로 기본 씬으로 돌아가므로 마지막 색으로 얼어붙지 않습니다.

밝기는 편집기 툴바의 Brightness 슬라이더로 즉시 바뀝니다(0–255). 픽셀이 하나라 전력 여유가 넉넉하니 255까지 올려도 안전합니다.

파일 위치와 백업

플랫폼경로
Linux~/.config/macrokey/
macOS~/Library/Application Support/MaduinosMacroKey/
Windows%APPDATA%\MaduinosMacroKey\
파일내용
profile.json키맵 · 액션 · 호스트 액션 · LED 색
settings.json포트 · 자동 연결 · LED/AgentPet 사용 여부 · 녹화 최소 간격

백업은 profile.json 하나만 복사하면 됩니다. MACROKEY_CONFIG_DIR 환경 변수로 위치를 바꿀 수 있어서, 설정을 저장소에 두고 심볼릭 링크로 관리해도 됩니다.

키패드 자체가 백업입니다. 프로필은 장치 EEPROM에도 들어 있으므로 PC를 바꿔도 macrokey pull --save 한 번이면 키맵을 되찾습니다. 다만 호스트 액션은 PC에만 있습니다 — 장치는 토큰 번호만 기억합니다. 이미지 붙여넣기나 셸 명령을 쓰고 있다면 profile.json을 따로 챙기세요.

레시피

자주 쓰는 단축키 8개를 바로 얹기

가장 흔한 사용법. 레이어 0의 TAP 8칸을 원하는 단축키로 바꾸고 장치에 씁니다. 여기까지는 앱을 꺼도 동작합니다.

Base 탭 → 각 행의 Tap 칸 클릭
Action: key
Value: ctrl+shift+p
→ Write to device

실수하면 곤란한 동작을 DOUBLE에

"전체 빌드 삭제"처럼 되돌리기 어려운 것은 TAP이 아니라 DOUBLE에 넣습니다. 그 키의 TAP은 250 ms 늦어지니, 자주 쓰는 키는 피하세요.

Double 칸 → Action: host
Value: 9   (profile.json에 9번 정의)

레이어를 하나 더 열기

기본은 8번 HOLD로 레이어 1만 씁니다. 7번 HOLD에 레이어 2를 걸면 슬롯이 8개 더 생깁니다.

Base 탭 → 7행 Hold 칸
Action: layer_momentary
Value: 2

자주 쓰는 문구 붙여넣기

이메일 서명이나 주소처럼 긴 텍스트는 장치에 안 들어갑니다. 호스트 액션 text로 만들고 키를 토큰에 연결합니다.

profile.json:
"3": { "type": "text",
       "params": { "text": "..." } }

편집기: Action: host / Value: 3

프로그램 실행 버튼 만들기

shell은 실행하고 기다리지 않습니다. 프로그램이 끝날 때까지 막히지 않도록 일부러 그렇게 돼 있습니다.

"4": { "type": "shell",
       "params": { "command": "code ~/work" } }

빌드 상태를 LED로 보기

CI 스크립트나 빌드 훅에서 상태를 흘려보내면 픽셀이 반응합니다.

macrokey daemon &
make && macrokey state success \
     || macrokey state error

12

지금은 안 되는 것

설계 문서에 있지만 아직 손이 닿지 않은 부분입니다. 문서를 믿고 찾다가 헤매지 않도록 적어 둡니다.

기능현재 상태
앱별 자동 레이어 전환 활성 창을 읽는 백엔드와 set_app_layer_rules() API는 있지만 아무 데서도 호출하지 않습니다. 설정 파일에 규칙을 적는 자리도 아직 없습니다.
호스트 액션 편집 GUI 토큰 지정만 가능. 실제 내용은 profile.json 직접 편집 (녹화로 만드는 경우는 예외)
미디어 키 (consumer) MK_USE_HID_PROJECT=1로 다시 빌드해야 동작
마우스 이동 · 휠 펌웨어와 프로토콜에는 있지만 편집기에서 고를 수 없음. profile.json을 직접 고치면 사용 가능
장치 매크로 (sequence) EEPROM에 480 B가 배정돼 있지만 편집기에 만드는 화면이 없음
진행률 바 픽셀이 1개라 밝기 변조로 대체 (스트립으로 늘리면 코드 변경 없이 바가 됨)
