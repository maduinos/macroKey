macroKey 사용 설명서

버튼 8 × 바인딩 가능한 제스처 2 = 16 슬롯. 펌웨어 · 호스트 앱 0.4.0. 배선은 wiring.html을 보세요.

앱이 없어도 키패드는 동작합니다. 펌웨어만 올리면 평범한 USB HID 키보드이고, 앱은 긴 텍스트·셸 명령·LED 상태 표시를 얹는 증폭기입니다.

01시작하기

Pro Micro는 리셋 버튼이 없습니다. RST–GND를 빠르게 두 번 단락시켜 부트로더(8초)를 띄운 직후에 upload를 실행하세요.

arduino-cli compile --fqbn SparkFun:avr:promicro:cpu=16MHzatmega32U4 firmware
arduino-cli upload  --fqbn SparkFun:avr:promicro:cpu=16MHzatmega32U4 -p /dev/ttyACM0 firmware

여기까지만 해도 키 8개가 Ctrl+Alt+Shift+1~8을 보냅니다. 앱은 선택입니다.

python -m pip install -e ".[gui,input]"          # Linux / macOS
python -m pip install -e ".[gui,input,windows]"  # Windows (이미지 클립보드 포함)
python -m pip install -e .                       # 헤드리스 (CLI만, Qt 없이)

macrokey          # 편집기 창 (기본값)
macrokey ports    # 포트 목록. * 가 유력 후보
macrokey info     # 펌웨어 · 프로토콜 · 프로필 동기화 여부
macrokey monitor  # 키를 누르면 이벤트가 찍힘 — 조립 직후 배선 확인용

pyserial만 필수입니다. PySide6가 없으면 편집기 창만, pynput이 없으면 녹화와 호스트 액션만 비활성화됩니다. 포트가 안 보이면 sudo usermod -aG dialout $USER 후 재로그인.

02누르는 방식

제스처동작발화 시점주로 넣는 것
TAP짧게 눌렀다 뗌뗄 때 즉시기본 단축키
DOUBLE250 ms 안에 두 번두 번째 탭되돌리기 어려운 동작
HOLD3초 단독 유지3초 도달바인딩 불가 — 녹음 진입점

DOUBLE을 안 쓰는 키는 느려지지 않습니다. 해당 키의 DOUBLE 슬롯이 비어 있으면 TAP을 떼는 즉시 내보내고, 채워져 있을 때만 250 ms를 기다립니다. 자주 쓰는 키에는 DOUBLE을 비워 두세요.

HOLD에는 아무것도 바인딩할 수 없습니다. 키 하나를 단독으로 3초 누르는 것이 녹음을 여는 방법이기 때문입니다. 그래서 바인딩 가능한 슬롯은 키당 TAP · DOUBLE 두 개, 전부 16개입니다.

녹음은 패드에서 시작하고 끝냅니다. 키를 단독으로 3초 누르면 픽셀이 빨갛게 맥동하며 녹음이 시작되고, 같은 키를 다시 3초 누르면 저장됩니다. 탭한 뒤 곧바로 다시 눌러 3초 유지하면 DOUBLE 슬롯에 녹음되고 픽셀은 분홍입니다.

레이어와 코드(chord)는 제거되었습니다. 레이어는 보이지 않는 모드와 외워야 하는 진입 방법을 만들었고, 코드는 편집 수단이 없어 채울 방법이 없었습니다. 두 영역이 쓰던 EEPROM은 지금 매크로 레코드가 씁니다.

기본으로 들어 있는 것

키 · 제스처동작
1–8 TAPctrl+alt+shift+1 … 8
1–8 DOUBLE비어 있음 — 탭 후 3초 홀드로 녹음해 채웁니다

미디어 키는 기본 빌드에서 나가지 않습니다. AVR 코어의 Keyboard에는 consumer page가 없어 펌웨어가 시리얼로 보고만 합니다. 쓰려면 arduino-cli lib install "HID-Project" 후 Config.h의 MK_USE_HID_PROJECT를 1로 바꿔 다시 올리세요.

03키 설정하기

macrokey를 인자 없이 실행하면 편집기가 열립니다. 키 8행 × 제스처 2열 격자로 16슬롯이 그대로 화면에 있습니다. 칸을 클릭 → 단축키를 누르거나 녹음. 값은 OK를 누르는 순간 검증됩니다.

Save도 Write도 없습니다. 편집이나 녹음이 끝나면 그 자리에서 저장되고 키패드에 기록됩니다. 연결할 때도 장치와 대조해 다르면 맞춥니다. 눌러야 반영되는 버튼이 있으면 누르는 걸 잊었을 때 화면과 키가 서로 다른 말을 하게 되므로 전부 없앴습니다. macrokey push · macrokey pull은 남아 있습니다.

ActionValue실행예
key단축키 문자열장치ctrl+shift+p
consumer미디어 키 이름장치volume_up
mouse_buttonleft · right · middle장치middle
sequence매크로 슬롯장치녹음이 만듦
host토큰 0–255PC7
none——비우기

단축키 문법 — 수식키를 +로 잇고 마지막에 일반 키 하나. 순서 무관. ctrl(control) · alt(option) · shift · gui(win·cmd·super) · rctrl ralt rshift rgui(오른쪽). 수식키만 넣어도 되고, 일반 키를 두 개 이상 넣으면 거부됩니다.

미디어 키 이름 — volume_up volume_down mute play_pause stop next_track prev_track brightness_up brightness_down

04매크로 녹화

패드에서 직접 합니다. 키 하나를 단독으로 3초 누르면 녹음이 시작되고, 같은 키를 다시 3초 누르면 저장됩니다. 앱은 켜져 있어야 하지만(캡처는 PC가 합니다) 창을 볼 필요는 없습니다. 편집 창의 Record…와 macrokey record --key 3도 그대로 있습니다.

동작들어가는 슬롯픽셀
홀드 3초TAP빨강 맥동
탭 → 홀드 3초DOUBLE분홍 맥동

저장되면 픽셀이 결과를 알려줍니다 — 초록은 키패드에 저장(앱을 꺼도 동작), 주황은 호스트 액션(이 PC가 켜져 있어야 동작), 빨강은 저장 안 됨. 캡처된 스텝은 창에 목록으로 뜨고 ~/.config/macrokey/macrokey.log에도 남습니다.

앱이 자동으로 정리합니다: 수식키 접기(ctrl↓ c↓ c↑ ctrl↑ → hotkey ctrl+c) · 지연 양자화(10 ms 단위, 40 ms 미만 버림) · 연속 문자 병합(낱개 타자 → text 하나) · 패드 자신의 입력 제외 · 비밀번호로 보이는 구간 제거(sudo 등을 실행하고 Enter를 친 직후의 텍스트).

재생은 녹음보다 빠릅니다. 연속으로 친 글자는 타이핑 속도를 기록하지 않고 text 하나로 합쳐지며, 패드가 일정한 속도로 다시 칩니다 — 2.7초 걸려 친 15글자가 기본값에서는 0.075초에 재생됩니다. 사람 손 속도를 그대로 재현하는 건 대개 원하는 바가 아니라서 그렇습니다.

받는 쪽이 따라오지 못하면 툴바의 Typing 값을 올리세요. 글자당 대기 시간(ms)이고 default는 5 ms입니다. 40 ms면 위 15글자가 0.6초가 됩니다. 이 값은 프로필에 저장되므로 앱을 꺼도 패드가 그 속도로 칩니다.

2초를 넘는 멈춤은 2초로 잘립니다. 더 긴 대기가 필요하면 녹음할 때 나눠서 쉬세요.

마우스가 든 녹음은 커서를 화면 좌상단으로 보내고 시작합니다. 커널은 마우스 이동을 상대값으로만 알려주기 때문에, 기준점이 없으면 재생할 때 커서가 있던 자리에서 움직여 엉뚱한 곳을 클릭합니다. 녹음도 재생도 같은 구석에서 출발하면 같은 픽셀에 떨어집니다. 커서를 옮기는 건 패드 자신입니다 — 진짜 USB 마우스라서 Wayland에서도 동작합니다.

장치 액션 하나로 표현되면 EEPROM에 굽고, 시퀀스로 컴파일되면 매크로 슬롯에, 장치가 재생할 수 없는 것(클립보드·셸·한글)만 호스트 액션이 됩니다. 이 배치는 앱이 알아서 합니다.

05호스트 액션

EEPROM 1 KB에 못 넣는 것들입니다. 장치는 EV t=host tok=N 한 줄만 흘리고 실제 일은 PC가 합니다. 앱이 꺼져 있으면 아무 일도 일어나지 않습니다.

호스트 액션을 만드는 GUI는 아직 없습니다. 편집기에서는 토큰 번호만 고르고, 그 토큰의 실제 내용은 profile.json의 host_actions를 직접 편집합니다 (녹화는 예외 — 토큰을 자동으로 만들어 줍니다).

type하는 일params
hotkey단축키 전송hotkey, hold_ms
text텍스트 타이핑text
clipboard_image이미지를 클립보드에 넣고 붙여넣기path, paste, press_enter
shell명령 실행 (기다리지 않음)command, cwd
delay대기ms
sequence여러 액션을 순서대로steps
stop실행 중인 호스트 액션 중지—
noop아무것도 안 함—

기본 프로필에는 호스트 액션이 없습니다. 녹음이 장치에 안 들어갈 때 앱이 토큰을 만들어 주고, 직접 쓰려면 profile.json의 host_actions에 아래처럼 넣은 뒤 그 토큰을 키에 바인딩합니다.

"host_actions": {
  "0": {
    "type": "text",
    "name": "서명",
    "params": { "text": "정우현 / Maduinos\n" }
  },
  "1": {
    "type": "shell",
    "name": "터미널 열기",
    "params": { "command": "gnome-terminal" }
  },
  "2": {
    "type": "sequence",
    "name": "회의록 템플릿",
    "params": { "steps": [
      { "type": "hotkey", "params": { "hotkey": "ctrl+n" } },
      { "type": "delay",  "params": { "ms": 300 } },
      { "type": "text",   "params": { "text": "## 회의록\n일시: " } }
    ] }
  }
}

path는 ~를 풀어 주고, 상대 경로면 profile.json이 있는 설정 폴더 기준입니다. command는 문자열이면 셸 문법으로 쪼개지고 배열이면 그대로 전달됩니다. 시퀀스에는 최대 스텝 수와 총 실행 시간 상한이 있고, 1번+2번 동시가 즉시 중지입니다. 호스트 액션은 장치에 쓰지 않으므로 push가 필요 없습니다 — 앱만 다시 시작하면 반영됩니다.

명령하는 일

07LED로 상태 보기

픽셀 하나가 세 소스를 우선순위로 합성합니다: 1 키 누름(흰색 120 ms, 어느 키든 동일) → 2 호스트 앰비언트(녹음 중 빨강 · 분홍, 저장 결과 초록 · 주황 · 빨강) → 3 기본 씬.

macrokey daemon &
macrokey state running --progress 0.5
macrokey state error --severity critical
상태색효과
idle어두운 청록solid
thinking · planning보라breathe
reading파랑solid
editing초록solid
running청록pulse
waiting노랑blink (느림)
approval주황blink (빠름)
success초록flash 후 감쇠
error빨강blink
offline소등—

--progress는 픽셀이 1개라 밝기로 나타납니다(0.3 → 30% 밝기). 앱을 끄면 3초 뒤 장치가 기본 씬으로 돌아가므로 마지막 색으로 얼어붙지 않습니다. 밝기는 툴바 슬라이더로 0–255, 255까지 올려도 전력은 안전합니다.

플랫폼경로

profile.json(키맵 · 액션 · 호스트 액션 · LED 색)과 settings.json(포트 · 자동 연결 · LED/AgentPet · 녹화 최소 간격). 백업은 profile.json 하나면 되고, MACROKEY_CONFIG_DIR로 위치를 바꿀 수 있습니다.

키패드 자체가 백업입니다. 키맵은 장치 EEPROM에도 있어 macrokey pull --save 한 번이면 되찾습니다. 다만 호스트 액션은 PC에만 있습니다 — 장치는 토큰 번호만 기억합니다.
